# 飞书妙记与议案接入说明

## 已实现的数据流

1. 前端带着飞书会议表记录 ID 进入“会议纪要”。
2. 后端读取会议表、公司主体表、妙记链接、会议纪要正文和关联议案。
3. 前端优先显示已经取得的数据，只提示确实缺少的内容。
4. “按类型生成议案”根据股东会、董事会、监事会分别生成议案，并在飞书“议案表”创建记录。

## 公司名称规则

系统按以下顺序确定公司名称：

1. 飞书“公司主体表”的“公司名称”；
2. 当前会议记录里的“公司名称”；
3. 用户在前端填写并保存的公司名称；
4. 都没有时显示 `XXX有限公司`。

如果飞书或用户输入的是完整登记名称，例如“上海甲乙股份有限公司”或“上海甲乙有限公司”，系统原样使用。

如果只输入简称：

- 主体类型含“股份”，补成“简称+股份有限公司”；
- 其他主体补成“简称+有限公司”。

## 飞书表格建议字段

### 公司主体表

| 字段 | 类型 |
|---|---|
| 公司名称 | 单行文本 |
| 公司类型 | 单选或单行文本 |

“公司类型”可以填写“股份有限公司”或“有限公司”。

### 会议表

| 字段 | 类型 |
|---|---|
| 妙记链接 | 超链接 |
| 会议纪要正文 | 多行文本 |

## Render 可选环境变量

如果暂时没有“公司主体表”，可以增加：

```text
FEISHU_COMPANY_NAME=实际登记的公司全称
```

有“公司主体表”时不需要这个变量。

## 妙记正文处理

接口直接读取妙记标题、时长、所有人和链接。正式会议纪要优先读取会议表中的“会议纪要正文”“妙记逐字稿”或“会议纪要”字段。

妙记原始转写可能继续编辑，也可能包含口语内容，因此建议确认后再写入正式会议纪要字段。

## 会议列表过滤

文书中心“股东会文件”只显示股东会；董事会和监事会各自只显示对应类型的会议。
