# 飞书多维表格与智能体设计方案

## 一、读取结论

已成功解析 `会议合规管理系统-2.base`，可以直接读取其中的表结构、字段、工作流和 AI 提示词。

现有 Base 包含 12 张表：会议表、议案表、人员表、表决表、风险表、法规索引表、待办表、文书模板表、股东表、文书表、会议类型分类表、会议批次表。

现有 Base 包含 3 个工作流：

1. `会议合规AI审查工作流`：已启用，但其中两个 AI 节点实际都在做模板替换，不是真正的合规审查。
2. `三会文书自动生成工作流`：未启用，且当前没有可执行步骤。
3. `股东大会文书自动生成`：已启用，流程可以保留，但提示词过于简单，缺少地点、召集人、通知、法定人数、表决结果、纪要正文和禁止虚构规则。

前端另有一个腾讯元器合规审查提示词。它可以保留，但需要增加会议类型、公司类型、公司章程、事实与法律依据区分、不得虚构和结构化输出要求。

结论：现有表格和自动化框架可以继续使用，不必全部推倒重来；现有 AI 提示词需要重写，空工作流需要重建。

## 二、现有 Base 的主要问题

1. 人员表中有 `会议表`、`会议表2` 至 `会议表5` 等重复反向关联字段，应删除，改为独立的“参会记录表”。
2. 人员表的“姓名”是飞书用户字段，外部股东、律师、审计师不一定有飞书账号，应改为文本姓名，并增加可选的“飞书账号”字段。
3. “任期起止”只有一个日期，应拆成“任期开始”和“任期结束”。
4. 会议表缺少结束时间、地点、召开方式、通知日期、通知方式、应到人数、实到人数、法定人数判断、散会时间和归档文件夹。
5. 没有独立的“参会记录表”，无法准确记录应到、实到、列席、委托、回避、签到情况。
6. 没有独立的“纪要与原始材料表”，录音、转写稿、人工纪要和正式会议记录混在一起。
7. 议案表只有标题和分类，缺少议案正文、提案人、权限归属、关联交易、回避人员、提交股东会与否、拟决议文本。
8. 表决表缺少表决权数量、股份数量、有效票、无效票和表决结果计算字段。
9. 文书表的文书类型过少，无法覆盖通知、议程、签到表、表决票、统计表、议案、授权委托书和签署版文件。
10. 文书模板表的“是否启用”是文本字段，应改为复选框；模板应保存模板文件、模板正文、占位符清单和版本。
11. 会议类型分类表和会议批次表对当前前端不是必需，可以停用，避免用户理解成本。
12. Base 中只有一个泛称“文件夹”的块，没有形成规范的云文档归档目录。

## 三、推荐的多维表格结构

### 1. 公司信息表（新增）

用于确定适用的治理规则，避免把上市公司、非上市公众公司和普通有限公司混用。

核心字段：

- 公司编号：自动编号
- 公司名称：文本
- 公司类型：单选（有限责任公司、股份有限公司、上市公司、非上市公众公司）
- 证券市场及代码：文本
- 统一社会信用代码：文本
- 法定代表人：关联人员
- 注册资本：数字
- 公司章程：附件或云文档链接
- 股东会议事规则：附件或云文档链接
- 董事会议事规则：附件或云文档链接
- 监事会议事规则：附件或云文档链接
- 当前治理模式：单选（董事会+监事会、董事会审计委员会、不设董事会等）
- 状态：单选（有效、停用）

### 2. 人员表（修改）

保留现有表，删除重复会议反向关联字段。

核心字段：

- 人员编号：自动编号
- 姓名：文本
- 飞书账号：人员字段，可空
- 身份类型：多选（董事长、董事、独立董事、监事、监事会主席、董事会秘书、总经理、副总经理、财务负责人、股东代表、职工代表、律师、审计师、其他列席人员）
- 所属机构：多选（股东会、董事会、监事会、审计委员会、管理层、外部机构）
- 任期开始：日期
- 任期结束：日期
- 是否独立：复选框
- 是否股东：复选框
- 联系电话：电话
- 电子邮箱：文本
- 利益冲突及关联关系：多行文本
- 默认回避事项：多行文本
- 在任状态：单选（在任、离任、暂停履职）

### 3. 股东表（修改）

核心字段：

- 股东编号：自动编号
- 股东名称：文本
- 股东类型：单选（自然人、法人、合伙企业、其他）
- 对应人员：关联人员，可空
- 证件或统一社会信用代码：文本，前端展示时脱敏
- 持股数量：数字
- 持股比例：百分比
- 表决权数量：数字
- 表决权比例：百分比
- 联系人、电话、邮箱：文本
- 是否控股股东、是否实际控制人：复选框
- 状态：单选（有效、退出）

### 4. 会议表（修改，作为主表）

核心字段：

- 会议编号：自动编号
- 公司：关联公司信息表
- 会议名称：文本
- 会议类型：单选（股东会、董事会、监事会、审计委员会、其他）
- 会议性质：单选（年度、定期、临时）
- 届次及次数：文本
- 召集人、主持人、记录人：关联人员
- 开始时间、结束时间：日期时间
- 地点：文本
- 召开方式：单选（现场、视频、电话、通讯表决、现场与线上结合）
- 通知发出时间：日期时间
- 通知方式：多选（飞书、邮件、书面、电话、其他）
- 参会记录：关联参会记录表
- 议案：关联议案表
- 应到人数、实到人数：汇总字段
- 应有表决权、实际表决权：汇总字段
- 法定人数判断：公式
- 状态：单选（草拟、待通知、筹备中、进行中、待审核、已结束、已归档、已取消）
- 会议纪要：关联纪要与原始材料表
- 文书：关联文书表
- 风险：关联风险表
- 归档文件夹链接：URL
- 事实审核人、法律审核人：人员字段

### 5. 参会记录表（新增）

一行代表“某个人参加某一场会议”，解决人员表重复关联问题。

核心字段：

- 参会编号：自动编号
- 会议：关联会议表
- 人员：关联人员表，可空
- 股东：关联股东表，可空
- 参会身份：单选（应出席、列席、股东、代理人、律师、审计师、其他）
- 是否应到、是否实到、是否签到：复选框
- 到场方式：单选（现场、线上、委托、未出席）
- 委托人、代理人：关联人员或股东
- 委托书：附件
- 是否有表决权：复选框
- 表决权数量：数字
- 是否回避：复选框
- 回避议案：关联议案
- 进入时间、离开时间：日期时间
- 备注：文本

### 6. 议案表（修改）

核心字段：

- 议案编号：自动编号
- 关联会议：关联会议表
- 议案标题：文本
- 议案类别：单选（经营、投融资、担保、关联交易、任免、薪酬、利润分配、章程修改、股权激励、审计、其他）
- 提案人：关联人员或股东
- 背景：多行文本
- 议案正文：多行文本
- 拟决议文本：多行文本
- 审议权限：单选（股东会、董事会、监事会、经理层、待确认）
- 是否关联交易：复选框
- 关联方及回避人员：关联人员或股东
- 是否需要提交股东会：复选框
- 适用法规：关联法规索引表
- AI 审查状态：单选（未审查、审查中、通过、需修改、人工复核）
- 风险等级：单选（低、中、高、严重）
- 附件：附件

### 7. 表决表（修改）

一行代表“某一表决人对某一议案的一票”。

核心字段：

- 表决编号：自动编号
- 会议：关联会议表
- 议案：关联议案表
- 表决人：关联人员或股东
- 表决权数量：数字
- 表决意见：单选（同意、反对、弃权、未表决）
- 是否回避：复选框
- 是否有效：复选框
- 无效原因：文本
- 表决时间：日期时间
- 表决凭证：附件

同意数、反对数、弃权数、有效表决权比例和是否通过，使用公式与汇总字段计算，不交给 AI 猜测。

### 8. 纪要与原始材料表（新增）

核心字段：

- 纪要编号：自动编号
- 会议：关联会议表
- 来源类型：单选（录音、录像、妙记、人工笔记、转写稿、正式会议记录）
- 原始文件：附件
- 原始链接：URL
- 原始文本：多行文本
- AI 整理稿：多行文本
- 人工确认稿：多行文本
- 未确认事项：多行文本
- 版本号：数字
- 事实审核人：人员字段
- 审核状态：单选（待整理、AI 已整理、待事实确认、待法务审核、已确认）

### 9. 文书模板表（修改）

核心字段：

- 模板 ID：文本
- 模板名称：文本
- 会议类型：多选
- 文书类型：单选
- 生成阶段：单选（会前、会中、会后、归档）
- 模板文件：附件或云文档
- 模板正文：多行文本
- 占位符清单：多行文本
- 必填字段：多选或文本
- 使用的智能体：单选
- 模板版本：数字
- 是否启用：复选框

### 10. 文书表（修改）

文书类型增加：会议通知、通知回执、议程、签到表、授权委托书、议案、表决票、表决统计表、会议记录、会议纪要、会议决议、合规审查报告、其他。

其他核心字段：会议、议案、模板、文书正文、草稿文件、签署文件、版本号、生成状态、审核状态、审核人、签署状态、文件哈希、归档路径、生成时间、最后更新时间。

### 11. 风险表、待办表（保留并补充）

风险表增加：来源文书、来源纪要、发现方式、事实依据、处理期限、复核人、关闭说明。

待办表增加：任务类型、关联会议、关联议案、关联文书、完成证据、复核人。

### 12. 法规索引表（保留并补充）

增加：法规层级、发布机关、适用公司类型、适用会议类型、生效日期、失效日期、当前有效状态、全文附件、条文正文、人工校验人。

### 13. 建议停用的表

- 会议类型分类表：会议类型直接用会议表单选字段即可。
- 会议批次表：目前与前端业务重复。只有确实需要把多场会议打成一个项目包时再保留。

## 五、输入输出流与独立智能体

| 智能体 | 触发输入 | 写入输出 | 是否使用 AI |
|---|---|---|---|
| 人员数据整理 | 新增或导入人员 | 人员表、缺失项 | 是 |
| 会议筹备检查 | 新建或修改会议 | 合规评分、缺失项、风险表 | 是 |
| 议案审查 | 新增或修改议案 | 权限判断、风险、整改建议 | 是 |
| 纪要整理 | 上传录音转写或人工笔记 | AI 整理稿、未确认事项 | 是 |
| 会议通知生成 | 会议达到待通知状态 | 通知正文 | 是 |
| 会议议程生成 | 议案确认完成 | 议程正文 | 是 |
| 决议生成 | 表决完成 | 决议草稿 | 是 |
| 综合合规审查 | 文书提交审核 | 风险表、审查结论 | 是 |
| 归档命名 | 文书签署完成 | 文件名、目录、归档清单 | 是 |
| 签到表、委托书、表决票 | 结构化人员和会议数据 | 套模板文书 | 否，直接套模板 |
| 表决统计 | 表决记录 | 同意、反对、弃权和通过结果 | 否，使用公式 |

各智能体独立运行，不共享或保存所谓“思维链”，只读取完成任务所需的字段，并把明确结果写回对应表。

## 六、可直接使用的提示词

### 1. 人员数据整理智能体

```text
你是公司治理人员数据整理助手。

请把输入内容整理为：姓名、身份、所属机构、任期开始、任期结束、是否独立、是否股东、持股比例、电话、邮箱、关联关系、回避事项。

规则：
1. 原文没有的信息写“待补充”，不要猜。
2. 一个人可以有多个身份，但董事或高级管理人员兼任监事时必须提示人工检查。
3. 不输出身份证完整号码等不必要的敏感信息。
4. 最后只输出“整理结果”和“待补充信息”。

输入：{{人员原始内容}}
```

### 2. 会议筹备检查智能体

```text
你是三会会议筹备检查助手。

请根据公司类型、会议类型、公司章程、议事规则和会议信息，检查：召集人、通知时间、召开方式、主持人、参会人员、议案、应到人数和回避事项是否完整。

规则：
1. 只依据提供的章程和规则判断；没有依据时写“待人工确认”。
2. 不虚构通知期限、法定人数或人员身份。
3. 输出四部分：缺失信息、程序风险、修改建议、引用依据。

公司信息：{{公司信息}}
会议数据：{{会议数据}}
章程及规则：{{适用规则}}
```

### 3. 议案审查智能体

```text
你是公司三会议案审查助手。

请检查议案是否说明了背景、具体事项、金额或对象、提案人、审议权限、关联关系、回避人员和拟决议文本。

规则：
1. 判断该事项应由股东会、董事会、监事会还是经理层审议；证据不足时写“待人工确认”。
2. 发现关联交易、担保、投融资、任免或章程修改时单独提示。
3. 只引用输入中提供的法规或制度，不编造条文。
4. 输出：议案分类、缺失项、权限风险、利益冲突、修改建议、依据。

议案：{{议案内容}}
公司信息：{{公司信息}}
适用规则：{{适用规则}}
```

### 4. 会议纪要整理智能体

```text
你是会议纪要整理助手。

请把录音转写或人工笔记整理为正式会议记录草稿，包括：会议基本信息、出席和列席人员、法定人数情况、逐项议案、讨论摘要、回避情况、表决结果、形成的决定、待办事项和散会时间。

规则：
1. 不增加原文没有发生的发言、表决或决定。
2. 听不清、互相矛盾或缺失的内容写“【待确认】”。
3. 不写冗长逐字稿，只客观概括讨论要点。
4. 表决结果必须与表决表一致；不一致时列入“待确认事项”。
5. 输出标题、正文和待确认事项。本稿标注“草稿，待事实审核和法务审核”。

会议数据：{{会议数据}}
参会记录：{{参会记录}}
表决结果：{{表决结果}}
原始纪要或转写：{{原始文本}}
```

### 5. 会议通知生成智能体

```text
你是会议通知起草助手。

请严格按照会议通知模板，把公司名称、会议名称、召集人、时间、地点、召开方式、出席人员、列席人员、议案、联系人、回复期限和附件清单填入正文。

规则：
1. 不改变模板结构和固定条款。
2. 缺失信息保留“【待补充：字段名】”，不得猜测。
3. 不自行添加未确定的议案。
4. 只输出通知正文。

模板：{{通知模板正文}}
会议数据：{{会议数据}}
人员数据：{{参会数据}}
议案数据：{{议案数据}}
```

### 6. 会议议程生成智能体

```text
你是会议议程生成助手。
```

### 7. 会议决议生成智能体

```text
你是会议决议起草助手。

请根据已确认的议案文本和表决结果，逐项生成决议草稿。

规则：
1. 只有表决结果显示通过的议案才能写成“审议通过”。
2. 必须写明同意、反对、弃权和回避情况。
3. 不得扩大授权范围，不得增加表决表中没有的决定。
4. 数据缺失或矛盾时停止形成该项决议，写“【待确认】”。
5. 输出决议正文，并标注“草稿，待法务审核和签署”。

会议数据：{{会议数据}}
议案：{{议案数据}}
表决结果：{{表决汇总}}
决议模板：{{决议模板}}
```

### 8. 综合合规审查智能体（替换前端腾讯元器现有提示词）

```text
你是公司三会文书合规审查助手。

请根据公司类型、会议类型、公司章程、议事规则和法规库，审查输入文书的事实一致性、召集通知、出席与法定人数、审议权限、利益冲突与回避、表决、签署、附件和信息披露。

规则：
1. 区分“文书已经证明的事实”和“仍需核实的信息”。
2. 不编造法律条文；没有依据时写“未找到依据，待法务确认”。
3. 不因为格式问题直接认定决议无效。
4. 每个问题输出：问题、风险等级、事实依据、规则依据、修改建议、责任人建议。
5. 最后输出“可以进入人工审核”或“应先补充材料”，不要输出“已合法有效”。

公司信息：{{公司信息}}
会议信息：{{会议信息}}
参会与表决：{{参会和表决数据}}
待审文书：{{文书正文}}
适用规则：{{规则内容}}
```

## 七、现有工作流的改造方式

### 会议合规AI审查工作流

- 保留触发器、风险表写入、待办创建和飞书通知。
- 删除两个“仅凭模板 ID 或云文档链接生成正文”的提示词。
- 改用“综合合规审查智能体”。
- 云文档不能只传网址；应先读取文档正文，再把正文传给智能体。

### 三会文书自动生成工作流

- 当前为空且未启用，重新建立。
- 不做一个超长万能工作流。
- 分成通知、议程、纪要、决议四个独立自动化，分别调用对应提示词。
- 签到表、委托书、表决票和统计表直接使用模板与公式生成，不调用 AI。

### 股东大会文书自动生成

- 保留“新建会议—查找启用模板—循环生成—写入文书表—发送消息”的框架。
- 不再用一个通用提示词生成所有文书。
- 根据文书类型分别调用通知、议程、纪要或决议提示词。
- 生成前增加必填字段检查；缺失时把文书状态写为“需补充信息”，不生成看似完整的正文。

## 八、实施顺序

1. 先修改人员表、会议表，新建参会记录表和纪要与原始材料表。
2. 再修改议案、表决、模板和文书表。
3. 停用会议类型分类表和会议批次表。
4. 建立云文档文件夹和命名规则。
5. 先上线会议通知、纪要整理、合规审查三个智能体。
6. 验证数据准确后，再上线议程、决议和自动归档。

在正式采用会议纪要、决议或合规结论前，应由公司董事会秘书、法务或外部律师核对事实、章程依据、表决结果和签署要求。

## 九、主要设计依据

- 《中华人民共和国公司法》要求对会议决定制作和保存会议记录；股份有限公司股东会记录还应与出席股东签名册、代理委托书一并保存。因此本方案把参会、委托、表决、纪要和签署版文件分别结构化保存：https://www.npc.gov.cn/npc/c2/c30834/202312/t20231229_433999.html
- 非上市公众公司治理规则强调召集、提案审议、通知、程序、授权委托、表决、决议及会议记录的完整安全保存。因此本方案没有只保存最终决议，而是保留会前、会中、会后证据链：https://www.csrc.gov.cn/csrc/c106256/c1653982/content.shtml
